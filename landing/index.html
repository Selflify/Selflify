Feature set

Everything stays close to the server reality.

Selflify avoids “platform magic”. It works directly with the same files, domains and runtime processes that already exist on your box.

Single source of truth

`selflify.config.json` drives UI, DNS sync, generated Caddy config and cleanup jobs.

Zero-downtime config apply

Changes validate and reload through Caddy admin API instead of brute-force container restarts.

Preview auth built in

Set preview login/password in the panel. Under the hood Selflify uses `caddy hash-password`.

Cloudflare-aware

Create sites and keep wildcard DNS aligned with the server IP without manual dashboard work.

Filesystem-first deploy model

Stable and preview folders under `/var/www` are the deploy inventory. No extra storage layer.

Operational safety

Revision checks, snapshots, orphan storage and cleanup tasks keep mutations disciplined.

Workflow

What running Selflify actually looks like.

01

Bootstrap the server

Install Docker, unpack the bundle, seed `.env`, `selflify.config.json` and `Caddyfile`.

02

Open `/setup` once

Create the first account and fill in the main domain, server IP, Caddy email and Cloudflare token.

03

Manage sites from one panel

Create or edit sites, adjust preview auth, inspect deploy folders and remove obsolete previews.

04

Let the stack stay boring

Caddy, Cloudflare sync and cleanup all operate against the same file-backed runtime state.

Bootstrap

Fresh server to running panel in one command.

The installer downloads a prepared bundle, installs Docker, writes baseline runtime files and starts the production compose stack. 

curl -fsSL https://example.com/install-selflify.sh | bash -s -- \
  --archive-url https://example.com/selflify-bootstrap.tar.gz \
  --domain preview.example.com \
  --server-ip 203.0.113.10 \
  --email ops@example.com

What gets installed

Docker Engine, Docker Compose plugin, production compose files, baseline config and startup env.

What still happens in UI

The first login, Cloudflare token, site CRUD and preview auth are still managed through Selflify itself.

What stays editable

The landing is just static files, so you can tweak copy, layout and publish `dist/landing` to GitHub Pages.

Selflify is built for teams that want deploy previews without outsourcing the platform.
